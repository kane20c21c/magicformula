## 역할

매일 장 마감 후 **"내일 상대적으로 강할 5종목"** 을 골라 신호 JSON 을 만든다.
**판단(모델)은 여기가 소유**하고, 계좌·체결은 StockPortfolio `app/paper_day/` 가 소유한다.
4셀 분류 파이프라인과 같은 원칙 — *LLV 는 데이터 공급자지 판단자가 아니다*.

```
LLV (무수정)            → core/extend/ticker_classification.json 공급
   ↓ 읽기만
MagicFormula/mop_model  → panel · features · 매일 재학습 · 전 종목 순위  ★여기
   ↓ output/signals/signal_YYYY-MM-DD.json
StockPortfolio /day     → 데이 포트 가상계좌 (17:00 NXT 매수 + 당일고점 −1% 손절, 2026-07-30 −2%→−1%)
```

## 모델

- **LightGBM + CatBoost 앙상블** — 두 예측확률을 날짜별 백분위로 바꿔 평균
- **148피처** = BASE 48 + XS 45(전체 백분위) + G1 45(대섹터) + G5 10(소섹터)
- **상대타깃** `y_rel = (Gap_T1 > 그날 중앙값)`. `Gap_T1 = 익일시가/당일종가 − 1`
- **워크포워드** — 매일 "라벨 확정된 전 데이터"로 **처음부터 재학습**.
  warm-start 가 아니므로 **누적 저장할 모델 상태가 없다.** 남기는 건 그날의 순위와 학습 메타뿐.

### ⚠ 튜닝 금지
36개 설정 탐색 결과 test-holdout 상관 **−0.34**. 신호가 약해(AUC~0.56) 튜닝은
노이즈 적합 → 홀드아웃 악화. 하이퍼파라미터·피처는 고정, 트리만 갱신.

### ⚠ look-ahead 주의
`ticker_classification.json` 의 `r2/slope/cell4/signal_rules` 는 2025-04 이후
수익률로 역산한 값 — **절대 피처로 쓰지 말 것**. `sector` 필드만 사용한다.

### ⚠ 왜 features 를 LLV 로 못 옮기나
XS/G1/G5 100개 피처가 `groupby("Date").rank(pct=True)` — 그날 유니버스 전체
(2026-08-24 기준 **201종목**) 안의 횡단면 백분위다. 종목이 하나 추가/제외되면
**과거 전 구간 값이 바뀐다** → LLV parquet 의 종목단위 upsert 계약(`_upsert_and_recompute`, `SUPPLY_COLS` 보존)과
정면충돌. 게다가 lightgbm/catboost 의존성이 LLV 를 import 하는 전 프로젝트로 번진다.

★ **Top5 가 아니라 전 종목 순위**를 싣는다 — 소비자가 NXT 미거래 종목을 건너뛰고
차순위로 충원해야 하기 때문 (Kane 확정 2026-07-27).

### ⚠ `p` 는 확률이 아니라 **그날 유니버스 백분위**
타깃이 `y_rel = (Gap_T1 > 그날 중앙값)` 이라 원 확률부터 이미 '상대 우위 확률'이고,
최종 `p` 는 LGBM·CatBoost 두 확률을 각각 `rank(pct=True)` 로 바꿔 평균한 값
(`model.py` L78-80). 따라서 **거의 균등분포** — p ≥ 0.925 ≈ 상위 7.5% ≈ 10~14위.
"익일 갭상승 확률 85%" 같은 절대 해석은 불가능하다.

**소비자 계약 (StockPortfolio 데이 포트, Kane 확정 2026-08-03)**:
`p ≥ 0.925` 이고 `rank ≤ 15` 인 종목까지만 충원하고, **슬롯을 못 채우면 비워둔다**.
정본은 `StockPortfolio/app/paper_day/config.py` 의 `min_signal_p` / `fill_max_rank`
— 여기(mop_model)는 순위와 p 만 공급하고 컷은 하지 않는다.
⚠ 슬롯 수는 소비자 소관이고 **2026-08-24 부터 10슬롯**(`data/paper_day/config.json`
오버라이드)이다. 이 문서의 "Top5" 표기와 `strategy_id: mop_ml_top5` 는
**모델 이름의 잔재**일 뿐 슬롯 수를 뜻하지 않는다.
⚠ 청산 규칙은 **2026-08-31 부터 v1.1.2.3** — 쇼크일(TIGER200 갭≤−2% & 갭≤−3%
종목 ≥50) 관문 유예 + 15:00 거래량(MA20) 이월 판정. 정본·상세는 SP
`app/paper_day/config.py`·`app/paper_day/shockday.py`, 근거는 SP
`reports/데이포트_갭다운_시장단면_20260830.html` (케인 A/B 패턴).

## ⚠ 기각목록 — 다시 제안하기 전에 읽을 것

### 변동배율(YZ_20) 연동 청산 — **기각** (2026-08-17 Kane 결정)

스윙 포트 v1.2.0 의 손절폭 변동배율(`손절폭 = base × YZ_20 ÷ 직전 252거래일 스윙풀
중앙값`)을 데이 포트에 이식하려다 폐기했다. **배율의 물리적 근거는 확인됐지만 수익이
따라오지 않는다.**

확인된 것 — LLV core+extend 205종목 일봉 128,226행:
- YZ_20 ↔ 장중 고점→저가 하락폭 종목단위 Spearman **|0.956|**, 비율(하락폭÷YZ_20%)이
  분위별 1.265→1.075 로 거의 일정 → 선형 배율이 형식적으로는 타당
- 배율 적용 시 종목간 위험 정규화(익일하락폭÷손절폭의 5분위 최대/최소) **2.87 → 1.17**
- 척도는 **YZ20/252일**이 9조합(분자 5·10·20 × 분모 63·126·252) 중 5개 지표 전부 승.
  더 민감한 YZ10·YZ5 / 6개월은 **절대척도성이 0.862→0.496 으로 무너져** 폭락기에 배율이
  1.0 으로 눌린다 — 스윙에서 기각된 상대척도 실패 모드의 재현
- 변동성 효과 자체는 추세와 독립으로 존재한다: 2×2(변동성×추세) 셀에서 **두 추세군 모두**
  고변동 종목이 더 넓은 손절폭을 선호(비 1.60·1.67)

그런데 기각한 이유 — KIS 분봉으로 엔진을 그대로 모사(4종목 × 243거래일 = 968 에피소드):
- 현행 고정 1.0% 대비 **어떤 배율안도 통계적으로 구분되지 않는다**.
  고정 1.2% +0.007%p(t=+0.33) / 배율 지수0.3 +0.007%p(t=+0.24) /
  **스윙식 선형 배율 −0.048%p(t=−1.11)** — 방향이 오히려 열위
- `손절폭 = base × 배율^지수` 의 **최적 지수가 ~0** (0.3 까지 동률, 0.5 이상 단조 악화)

⚠ **원인은 구조적이다 — 이게 핵심이고, 파라미터를 바꿔도 해결되지 않는다.**
데이 포트 손절폭 1% 는 **장중 노이즈의 1/4**(장중 고점→저가 하락폭 중앙 −4.4%)이라
저변동 종목조차 도달률 95.7%, 나머지 분위는 100% 다. 배율로 0.7~2.5% 를 흔들어도 여전히
노이즈 안이라 결과가 안 바뀐다. 스윙은 손절폭 3~40% · 보유 20~60일이라 변동성이 손절
도달확률을 지배하지만, **데이는 추세가 지배하고 변동성은 부차적**이다. 결정적 반례 —
펩트론(배율 2.18, 최적 1.0%) vs 주성엔지니어링(배율 1.44, 최적 4.0%): 같은 고변동인데 정반대.

부수 확인: **현행 −1% 손절 자체는 유효**하다 — 무손절(익일 15:17 강제마감) 대비 4셀 모두
양수(+0.049~+0.146%p). 1.2% 가 근소 우위지만 유의하지 않아(t=+0.33) 변경 근거가 못 된다.
