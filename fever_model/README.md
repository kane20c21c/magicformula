# 현물게이지 (SpotGauge) — 시장 상태 관측기

> **⚠ 이 폴더는 MagicFormula 에서 독립할 예정이다** (Kane 결정 2026-08-26).
> 이관 절차는 `MIGRATION.md`. 이관이 끝나면 이 줄과 함께 `MIGRATION.md` 를 지운다.
> 이관 전까지는 `MagicFormula/fever_model/` 경로가 유효하다.

**한 줄**: "지금 장이 뜨거운가"를 재고(1단 온도), "그 안에서 누가 열을 내는가"를
줄 세운다(2단 발열계). **매수 신호가 아니다.**

## 왜 별도 리포인가

MagicFormula 는 스스로를 *"매매 룰의 **판단** 소유자"* 로 정의한다 — 진입가와
청산가를 내놓는 룰들의 집이다. 발열률만 그 정의에 맞지 않는다.

| | 황금률 · 데이 포트 · 스윙 포트 | **현물게이지** |
|---|---|---|
| 산출 | 진입·청산 **신호** | **관측 명단** (진입·청산 규칙 없음) |
| 대상 | 종목 선별 | **시장 상태** + 그 안의 종목 순위 |
| 소비자 | 투자포폴 8000 가상계좌 엔진 | 아웃퍼포머 8501 Temp.View + 메일 |
| 지평 | 1일 ~ 20거래일 | 20~60거래일 |

코드 결합도도 이미 0 이었다 — 2026-08-26 실측 기준 `fever_model` 이 다른 룰을
import 하는 곳도, 다른 룰이 `fever` 를 참조하는 곳도 **양방향 0건**이고,
MagicFormula `tests/` 6종 중 발열률을 다루는 것은 없다. 의존은 전부 리포 **밖**을
향한다(LLV · SP `.env` · 8501). 즉 분리는 코드 이동이 아니라 **문서와 스케줄 등록의
이동**이다.

`daily_WW_wf.py` 상수가 전부다 — 상세는 `CLAUDE.md` §파라미터 정본.

## 운영 (평일 KST)

| 시각 | 잡 | 내용 |
|---|---|---|
| 16:30 | `com.kane.fever-rule-daily` | 워크포워드 산출 (실측 ~10초) |
| 17:00 | `com.kane.fever-rule-mail` | HTML 메일 1통 |

```bash
python3 src/daily_WW_wf.py                  # 당일 1회 (일지에 있으면 skip)
python3 src/daily_WW_wf.py --force          # 같은 날짜 재계산
python3 src/send_fever_mail.py --dry-run    # 발송 없이 미리보기
```

## 형제 프로젝트와의 관계

```
longlivevault ──(OHLCV parquet 읽기)──▶ SpotGauge ──▶ 아웃퍼포머 8501 Temp.View
StockPortfolio ─(.env SMTP 재사용)────▶            └─▶ 17:00 메일
```

**단방향 소비자다.** 데이터는 LLV 에서만 받고, 다른 리포에 아무것도 쓰지 않는다.
LLV 16:00 KIS 종가 배치가 Weis·YZ 지표까지 재계산하므로 16:30 구동이 가능하다
(수급·Wyckoff 20:30 배치를 기다릴 필요가 없다).

## 항상 기억할 한계

- 유니버스가 현 시총 상위 기준 → **생존 편향**.
- 관측 기간이 **강세 사이클 하나** — 하락장 전량 미검증.
- 급등장에선 발열계 순위가 **베타(YZ) 순서로 쏠린다**.
- 온도 **절대 레벨은 캘리브레이션 의존** — 방향·상대 변화로만 읽을 것.
- 5일 단위 변화는 노이즈 — 20거래일 MA 로 읽는다.
